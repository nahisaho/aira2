# ADR-0002: Adapter pattern for pluggable LLM backends and credential storage

## Context / 背景
AIRA2 must support GitHub Copilot CLI (AIRA's existing sole backend), OpenAI,
Azure OpenAI, and Anthropic, selectable per user with project-level overrides
and admin-shared or user-overridden credentials (REQ-LLMBACKEND-001..008).
Each provider has a distinct SDK, auth scheme, and streaming protocol.

## Decision / 決定
Introduce a single `LlmBackendAdapter` interface (`chat`, `embed`,
`streamAgent`) with one adapter implementation per provider, resolved at
request time by a backend gateway using project-override-then-user-default
precedence. Provider credentials are stored in a dedicated encrypted
Credential Vault component, separate from the gateway, so vault security
review and key rotation are independent of adding/removing providers.

## Rejected alternatives / 却下した代替案
- Hard-coding a single backend (status quo from AIRA) — rejected because it
  directly contradicts the multi-backend requirement.
- One microservice per provider — rejected as unnecessary operational
  overhead (deployment, networking, auth) for what is a stateless request
  translation concern.
- Storing credentials inline in each adapter — rejected because it would
  duplicate encryption/masking logic across four adapters and complicate
  key rotation.

## Consequences / 結果
Adding a fifth provider requires only a new adapter class and vault entry
type, not gateway or caller changes. The vault becomes a single audited
component for REQ-LLMBACKEND-005/007 (encryption, masking). Adapters must
all conform to one contract, which may hide provider-specific capabilities
(e.g. provider-only features) unless explicitly extended.
