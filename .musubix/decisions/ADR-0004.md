# ADR-0004: Embed aira-synapse as a built-in supervised MCP service

## Context / 背景
`nahisaho/aira-synapse` already provides Graph RAG over a Rust-based
aira-graphdb engine with its own MCP server for Claude/VS Code Copilot. The
user requires its functionality merged into AIRA2 (REQ-GRAPHRAG-001..006,
013..015), configured the same way AIRA already handles per-project Agent
Skills and MCP servers (REQ-AGENTCONFIG-001..003).

## Decision / 決定
Run one supervised aira-graphdb (Rust) child process, with its own
isolated data directory, per project that has enabled the built-in Graph
RAG MCP server — not one shared process per AIRA2 deployment — fronted by
a built-in MCP server that AIRA2 registers automatically through the same
per-project Agent Skills/MCP configuration mechanism (DES-AIRA2-008) used
for user-added MCP servers, rather than requiring users to configure
aira-synapse as an external MCP server themselves. The Agent Skills/MCP
Configuration Manager (DES-AIRA2-008) and the Graph RAG Service
(DES-AIRA2-009) are kept as separate components: the former is a generic
per-project config/enablement surface, the latter is one specific built-in
MCP provider that registers itself through it and owns per-project process
supervision, restart-on-crash, and data isolation.

## Rejected alternatives / 却下した代替案
- Rewriting aira-graphdb's Rust engine in Node/TypeScript — rejected as a
  large, high-risk rewrite with no functional benefit; the existing engine
  is proven and independently maintained.
- Requiring users to manually add aira-synapse as an external MCP server
  (status quo) — rejected because it does not satisfy "merge the
  functionality" and duplicates configuration users would otherwise get
  by default.
- Making Graph RAG a hard dependency of the Agent Skills/MCP Configuration
  Manager itself — rejected to keep that manager generic and reusable for
  any future built-in or third-party MCP server, not coupled to Graph RAG.
- One shared aira-graphdb process/database for all projects — rejected
  because it cannot satisfy the project-isolation requirement (a crash or
  data issue in one project's graph must not affect another's), and it
  would need its own multi-tenant access-control layer duplicating
  DES-AIRA2-002 instead of relying on per-process/per-directory isolation.

## Consequences / 結果
AIRA2 must supervise (restart-on-crash, health-check) one external Rust
process per Graph-RAG-enabled project, unlike a pure-Node/TypeScript
stack; process/data-directory count scales with the number of projects
that enable the feature, which must be accounted for in capacity planning.
Graph RAG's generation-time LLM calls must be routed through the same LLM
Backend Gateway (DES-AIRA2-004) used elsewhere so REQ-GRAPHRAG-004's
backend-consistency requirement holds without duplicating provider logic.
